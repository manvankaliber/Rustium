# NET-COMPILE-INTEGRATION-REVIEW

**Disposition: repair / qualify before integration.** The direct proxy dependency has an unresolved process-wide implementation-ownership issue (R1); the prospective harness comparator is demonstrably fail-open on malformed or empty evidence (R2). The remaining changes are source-level candidates, conditional on current-identity compilation, link/ABI inspection and retained runtime tests. No expectation or required workload may be removed. This review ran no compiler, GN, Ninja, native test, benchmark or configured-tree write.

## Findings

### R1 ? P1: direct proxy edge duplicates the source-set across component images

`net-ordinary-compile-repairs/proposal/net/BUILD.gn:8497` adds `:proxy_value_rust_reference` directly to the connection source set. The retained pre-proposal graph and the currently generated `out/Default/obj/net/spdy_session_key_rust_reference.ninja` put all four proxy reference objects in `net_spdy_session_key_rust_reference.dll`; the five connection executable link rules import that DLL and currently contain zero proxy source-set objects. The proposed direct edge is intended to place those same object definitions into each connection executable to satisfy the seven unresolved methods. Thus there is one source-set compilation but a copy linked into the DLL and another into a consuming executable. A source-set dependency does **not** by itself establish one implementation for the process. We have not regenerated the proposal, inspected its final response files or binary symbol tables, and cannot determine precisely which definitions survive linker elimination or whether cross-image identity/state assumptions are safe. Linking successfully would not alone establish the requested single ownership.

Before accepting the edge, the integration owner should reconcile ownership deliberately: for example, create a single explicitly exported reference component for the frozen proxy implementations and import it consistently from the SPDY reference component and affected executables, with a narrowly scoped reference export macro; retain all type signatures, layouts, frozen bodies, case coverage and supported static/component configurations. An alternative must prove the same single-owner property without changing semantics. Re-evaluate the actual GN graph, link inputs and imports/exports, capture object/symbol ownership and verify a representative proxy construction, copy, destruction and comparison across the SPDY DLL boundary. Rebuild all affected references and consumers together. Do not solve the missing symbols by duplicating another implementation, weakening a test, or reusing production proxy policy. This is a source/graph finding, not a claim that a duplicate-definition linker error or a runtime bug has already occurred.

### R2 ? P2: comparator can report success for invalid or absent records

`net-ordinary-compile-repairs/compare_harness_records.py:20` checks field names but does not require records, required case/record counts, numeric types or finite durations. `json.loads` also accepts NaN and repeated object keys by default. `validate([])` succeeds; an in-memory record with `pair="bad"`, `cpp_ns="bad"`, `rust_ns=NaN` and `lifecycles=-1` passes `validate`. The stable projection discards durations, so two identically malformed or truncated files can compare successfully. Assertions disappear under `python -O`. This cannot establish either JSONL schema or full case membership even though the success message says so. No benchmark was run to demonstrate this input-validation defect.

Repair the comparator before using it as acceptance evidence: use explicit always-on errors, strict JSON parsing that rejects duplicate keys and non-finite constants, require exact record types/ranges (including finite numeric nonnegative durations, integral nonnegative pair index, positive lifecycle count, boolean order, and exact checksum syntax), and bind expected case IDs, count/order, pairs, lifecycle values, seed and verification records to the retained workload manifest or trusted baseline. Reject empty, truncated, duplicated or missing records, including two equally incomplete files. Compare duration *types and validity*, not duration equality; keep actual raw samples and provenance. Exercise positive and deliberately corrupt synthetic records without launching workloads; then compare retained actual verify output and parse timing records when separately authorized under benchmark policy.

## Source preservation and boundary assessment

* The `url/origin.h` proposal adds exactly a forward declaration and friendship for `net::cookie_partition_key_reference::SchemefulSite`; no serialization body or URL object layout changes. The frozen reference `SchemefulSite` still calls `Origin::Deserialize` and `SerializeWithNonceAndInitIfNeeded` directly, preserving the intended opaque-origin and nonce route rather than a public serialization fallback. The two reference headers explicitly qualify `::net` friends and all ordinary, DISABLED and FLAKY gtest friend class names. Verify retained opaque/nonce cases at runtime and actual URL component boundaries; private access alone is not evidence of their execution.
* The expected-value sites switch conditional checks to `has_value()` and keep payload/error arms; braces protect each gtest macro's outer `else`. The comparison matrix still iterates both complete cookie vectors. No expected result was weakened in these changes.
* `base/test/bind.h` at the reviewed local identity selects a `RepeatingCallback` for the changed const-call-operator capturing lambdas; `OnceCallback`'s converting constructor transfers its holder, so the receiving once API still permits only a single invocation. Captures and callback bodies are retained; the repeating change observer stays repeating. `set` copies its `label`; synchronous completion checks and `RunUntilIdle` bound local references in the reviewed examples. The cancellation case retains `backend` and callback counter across store destruction and deferred completion; terminal hook and DNS manager deletion deliberately allow receiver destruction during callback. These observations do not prove the implementation's cancellation, reentry or ownership behavior: run the unmodified tests and require their existing counts and assertions. Independently verify no outstanding callback dereferences stack state after its fixture returns.
* DNS HTTP job/interceptor virtual methods, and cache `Wall::Now`/`Ticks::NowTicks`, move out of line with corresponding defaulted destructors/constructors; the compared bodies retain operations, hooks and order. Both HTTP workload consumers and both cache consumers add their new `.cc` in the proposal. A newly out-of-line virtual destructor changes vtable/key-function emission, so it must be compiled/linked in each target, not assumed ABI-neutral. `Clocks` is noncopyable, declares wall before ticks and destroys ticks first; the timer points at its caller's accumulator for its lexical window. `raw_ptr` representation/instrumentation and dangling detection depend on configuration; verify the referenced objects outlive every callback/window and use actual platform builds. No new unsafe Rust or FFI body is present in these packet diffs.
* Both cookie performance sources preserve their fixed case IDs, input seeds, pair loops, alternating order, checksums and verification-before-timing; the store keeps its mock-clock verify mode, fixed business time, system-clock timing mode and `Sample` boundaries. Neither `--verify-only` nor the default reaches `Sample`; formatting occurs after each sample. Stream `setprecision(17)` is the `defaultfloat` general-format counterpart of `%.17g`, but source inspection does not establish byte-identical spellings, identical rounding across libraries, JSON finiteness, or immunity to a changed C++ global/stream locale. A locale with grouping or comma decimal punctuation can break JSON. Pin classic locale on output streams or use a locale-independent equivalent preserving 17 significant digits, validate finite numbers and round-tripping, and verify the actual downstream JSONL parser on representative exponent, decimal and integer-like values. Keep stdout/stderr separation and exact field names/order, case membership and timing boundaries. Do not compare measured durations for equality or time these checks as a benchmark.
* The DNS declarations add `NET_EXPORT_PRIVATE` only to `EnsureDnsReloaderInit`, `DnsReloaderMaybeReload` and `TranslateDnsRcodeForHttpssvcExperiment`; the two producer `.cc` files include their own headers. The separate auth packet adds only the eight named function/data annotations across five headers: Latin1 constant, normalization function, three `EntryMapKey` methods, `Identity` constructor, NTLM factory constructor and SSPI default constructor. All five frozen producer definitions include the corresponding header. Before/after header diffs show no changed body, data field, base, virtual declaration or signature. The captured Windows compile commands show `COMPONENT_BUILD` and `NET_IMPLEMENTATION` for all seven producer TUs, and neither flag ownership is inferred merely from a target name; `net.dll` query includes their objects. The connection original cache and proxy source-set commands lack `NET_IMPLEMENTATION`. The checked export macro maps to dllexport in the producer and dllimport in Windows consumers. These are source/old-graph observations: capture the *new* producer and consumer flags, exact decorated exports/import library and link results; export changes alter the component ABI surface. Non-Windows visibility and platform provider variants require their own evidence.
