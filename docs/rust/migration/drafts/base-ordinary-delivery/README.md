# Frozen base string-split validation proposal

This parent-only utility prepares a separate ordinary-test delivery for the original StringSplit family and the new typed bridge cases. It does not change the fixed networking or performance batch membership. It runs only after the configured consumer build completes successfully and a fresh Ninja dry run reports no work.

The plan selects `*SplitString*` from the launcher's complete test listing, then checks exactly one attempt for each selected enabled test. Disabled entries and native skips are separate from passes. The copied executable, declared resources, recursive adjacent DLL dependencies, selected source/configuration evidence and runner/helper bytes are hash-bound. Copies are independent, never hard links. System DLL providers and the installed Python runtime remain explicit host limitations. Execution logs and temporary files live outside the sealed snapshot under a short unique path.

The first script remains as source provenance with its CLI disabled. Independent review found that its filter omitted the bridge suite, parent XML could hide native skips, build identity was too loose, helper/controller copies were incomplete, and failures could escape without final records. The report is `evidence/base-ordinary-delivery-review-20261117.md`.

`ordinary_base_v2.py` is the replacement proposal. It retains the original `*SplitString*` selection and adds `StringSplitTest.*` and `StringSplitRustBridgeTest.*`, requires all five named bridge cases, and uses the independently qualified native-output parser for skip reporting. The diagnostic case must execute without a native skip before that contract passes. It explicitly binds the current applied 1,260-source authority, completed consumer build gate and tools, args, evaluated graph, generated base configuration, resulting runtime bytes and freshness. It copies and runs the controller/helpers, reconstructs empty runtime directories, and finalizes durable failures with independent post-run checks. Original Python/stdlib and nonadjacent DLL providers remain host limitations. No dynamic plugin closure is claimed.

The second source review remains a blocking historical report. Its runtime/build-identity finding requires a follower receipt; the active build driver must not be edited mid-run. `attest_build.py` is prepared to run the exact configured GN generation/check commands and actual serial consumer build after that job completes, then capture and recheck the complete graph/configuration and both consumer runtime identities inside its gate. The frozen test driver requires that completed receipt and its coordinator result, compares the recorded bytes with current inputs, and preserves both proofs.

The controller now requires one native RUN and one elapsed-time OK/SKIPPED terminal for every selected enabled case, reconciled with launcher attempts and the skip parser. Recap-only skip lines cannot prove execution. The parser is bound to its previously qualified frozen manifest and hash. Every launched process/probe has a deadline and post-launch cleanup path; cleanup failure is recorded as requiring process reconciliation. Parent finalization independently records artifacts even if the copied controller cannot finalize. Configuration membership is re-enumerated; the actual host interpreter and loaded Python DLL are identified and checked before/after. Remaining installed stdlib and system/nonadjacent/dynamic-provider limits stay explicit.

Prepared regression fixtures cover omitted bridge cases, filtered membership, extra/repeated attempts, native skips, absent/truncated/contradictory output, empty-directory membership, snapshot/helper drift, receipt/output and graph mismatch, timeout/cleanup failures, raw probe errors, and durable preparation/execution rejection. They have not run while the active configured build holds the gate. The material receipt/controller changes need independent source review and gated qualification before native execution. No native pass, ABI or cutover is established. No benchmark clocks, sanitizer/fuzz/security campaigns or publication are requested.
