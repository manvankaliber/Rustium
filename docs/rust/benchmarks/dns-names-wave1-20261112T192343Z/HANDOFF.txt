DNS names implementation handoff

Production: dns_names_util.cc/.h expose the same APIs, except that a new exported C++ DomainNameLess entry point backs the public inline DomainNameComparator. Consumers include no generated Rust header and link only the usual net export. All owned dotted/network/length/comparison/validation orchestration and canonicalization selection policy executes in safe Rust. No C++ DNS parsing fallback exists.

Remaining C++ seams:
- Existing IsCanonicalizedHostCompliant internet-hostname service (external URL policy).
- Existing HostStringIsLocalhost, IPAddress::AssignFromIPLiteral, ParseURLHostnameToAddress and their URL IP parser services. Rust preserves the original short-circuit order.
- Existing URL CanonicalizeHostVerbose/StdStringCanonOutput/ICU IDNA. Rust selects the original bytes for BROKEN and the URL result otherwise.
- C++ object ownership and adapters for std::string/vector/span/SpanReader. Cursor commits and copying happen in C++ callbacks; Rust decides every parsing step. Each reader input borrow ends before mutation. The post-advance payload copy preserves legal cursor/input object aliases. The bounded bridge chunk removes per-label heap allocation.
- Platform ABI, CXX runtime, allocator and Unicode service remain native dependencies.

Frozen baseline: original/ contains byte-for-byte original sources and helper snapshots with SHA-256 manifest. dns_names_reference.cc has original DNS algorithms and frozen hostname/localhost/IP wrapper helpers. Its comparator folds ASCII locally. URL parser/IDNA implementations are shared external services, never a newly migrated DNS helper. The preserved original dns_names_util_unittest.cc is unchanged.

Native validation: build_native.py uses the configured Clang/Rust toolchain and captured configured C++ flags, but no GN/Ninja/build-tree writes. Native production is the actual owned dns_names_util.cc, not an adapter replacement. Native service methods in native_seams.cc are extracted exact bodies from the unmodified URL/IP sources to avoid loading an unrelated stale net.dll dependency chain. Original CreateNamePointer is extracted for the unchanged test. They are service scaffolding only, not a new production algorithm. URL/ICU DLL dependencies and runtime data are copied into this scratch directory for deterministic native loading. These copies are not edits to the configured worktree.
