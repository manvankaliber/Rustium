Define the finish line first

All shipped browser-owned code and bundled executable dependencies use Rust: shell, services, renderer, JavaScript engine, graphics, media and release helpers. No retained Chromium engine hidden behind FFI or a webview. OS APIs, system drivers and user-loaded web content are outside the implementation boundary. Build tools, tests and data formats are tracked separately.

Seven gated milestones

01Scope & prove the baselineStart here · proposed

Map Windows, macOS and Linux build targets, runtime processes, bundled libraries and desktop features. Measure the actual shipped dependency graph rather than repository totals.

chrome/ · content/ · BUILD.gn · DEPS · build/

Exit gate: Reproducible baseline builds; feature inventory; dependency and license manifests; agreed compatibility, accessibility, performance and security budgets.
02Rust foundations & migration seamsEnables all tracks

Establish ownership, task scheduling, file I/O, errors, logging and IPC contracts. Extend existing Rust footholds in base, URL, CBOR, package parsing and data decoding. Keep temporary bridges small and explicitly owned.

base/ · url/ · mojo/ · sandbox/ · components/cbor/

Exit gate: One production vertical slice builds and runs in Rust on every target OS; protocol and lifetime tests pass; unsafe and FFI boundaries are inventoried.
03Native desktop shell & product featuresProduct track

Move windows, tabs, navigation UI, menus, dialogs, settings and accessibility into Rust. Migrate profiles, history, bookmarks, downloads, permissions, credential integration, policies and extension-facing browser APIs. A temporary legacy renderer may remain during this stage.

chrome/browser/ · ui/ · components/ · extensions/

Exit gate: Feature-matrix parity, keyboard and screen-reader flows, crash recovery and profile migration pass across desktop platforms. The shell milestone alone does not qualify as 100% Rust.
04Network, storage & isolated servicesParallel after 02

Migrate HTTP, TLS integration, DNS, proxy, cookies, cache and certificates; then origin storage, databases, service workers, permissions and service processes. Replace native libraries or document remaining blockers. Preserve on-disk data and security boundaries.

net/ · services/ · storage/ · sql/ · crypto/ · device/

Exit gate: Differential protocol and persistence tests, malformed-input fuzzing, sandbox checks and upgrade/rollback tests pass; no silent profile data loss.
05Rust web platform & execution engineCritical path

Replace Blink and V8 implementation: parsing, DOM, CSS, layout, painting, accessibility tree, JavaScript, garbage collection, WebAssembly and browser bindings. Carry Web APIs, extensions and developer tooling through the transition. This is a browser-engine program with separate staffed workstreams.

third_party/blink/ · v8/ · content/ · gin/ · extensions/

Exit gate: Agreed Web Platform Tests, JS/Wasm conformance, real-site compatibility, process isolation and responsiveness thresholds pass. Legacy engine can be removed from candidate builds.
06Graphics, media & native dependency closureParallel research from 01

Replace bundled C/C++ rendering, compositing, GPU translation, fonts, image codecs, audio/video, WebRTC, PDF and printing implementations. Integrate Rust OS bindings. Resolve required proprietary media and platform compatibility constraints explicitly.

gpu/ · cc/ · skia/ · media/ · pdf/ · printing/ · third_party/

Exit gate: Required workloads, visual output, media interoperability and GPU recovery meet the baseline; binary dependency audit finds no bundled non-Rust runtime implementation. Any retained native component blocks the strict target.
07Cut over, remove legacy & shipFinal acceptance

Finish Rust startup, crash handling, installer, updater and migration helpers. Remove C/C++ bridges, legacy targets and browser-owned JS/TS UI. Preserve legal attribution; stage release rollout with verified rollback.

chrome/app/ · chrome/installer/ · build/ · release artifacts

Exit gate: All required desktop features pass on clean release builds; every shipped executable dependency is accounted for; no legacy fallback is required; stability, performance, accessibility and security gates pass.

Dependency map

01 Baseline→02 Foundations→03 Shell + 04 Services + 05 Engine→07 Release

06 Graphics/media research starts at 01; implementation shares 02 foundations and must converge with 05 before 07. Engine compatibility and native dependency closure govern the final date.

How to measure real progress

MeasureRequired at completion
Shipped implementationEvery owned runtime target and bundled library audited as Rust
Desktop feature parityAll required feature and platform acceptance cases pass
Legacy dependency countZero shipped C/C++ engines, libraries or temporary bridges
Release qualityCompatibility, security, accessibility and performance budgets pass

Planning constraint: No milestone is marked complete from source inspection alone. Percentage-by-phase and calendar dates would imply evidence we do not have. Establish team capacity and measure a representative migration slice before estimating the full program.
