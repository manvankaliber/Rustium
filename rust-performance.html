Rust rewrite benchmarks

Chromium’s C++ baseline and our Rust implementation, measured through the real interface. Choose a view, then download a clean chart for sharing. Improvements and regressions are both included.

Benchmark methodology & sources

Read these as isolated operation benchmarks. Lower elapsed time is better. The default speedup is (C++ time / Rust time − 1) × 100: positive means faster, negative means slower. The optional time-saved view is (1 − Rust time / C++ time) × 100. For example, 20% less time is 25% faster. These are operation-level results, not whole-browser speedups. Black whiskers show bootstrap 95% confidence intervals for the comparison, not the range of individual timings. They describe these samples, not other machines or workloads.

Deferred candidates stay visible and are marked Candidate only, but are excluded from the aggregate. Small-operation equivalence uses a bound chosen before the acceptance run: the 90% paired-bootstrap interval for the absolute time difference must fit inside that bound. Actual improvements and slowdowns remain visible; an interval merely overlapping zero does not establish parity.

The load benchmark includes construction, warm-memory validation and destruction. Lookup benchmarks include the C++ interface and Rust bridge with packs already loaded. Disk I/O, resource decoding and browser startup are excluded. Lookup baselines use the preceding C++ lookup with the same Rust load-time validator; load baselines use the original C++ validator.

The original 25 DataPack cases are retained, including the tiny-pack load regressions. Later rewrites keep their measured versions in each chart's benchmark-run selector. Exact medians, bootstrap 95% intervals and archive links are available below each chart. The archived DataPack measurements and provenance are separate from this self-contained page; charts and PNG downloads work offline without them.
