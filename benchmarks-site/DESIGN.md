# Design plan

Rustium's benchmark console is a measurement instrument: navigation, a shared reference scale, and an evidence ledger. It is not a migration progress tracker, because the dataset does not establish whole-codebase completion.

Tokens: graphite #16191d (canvas), steel #20252b (panels), chalk #edf0f2 (type), slate #aeb7c2 (secondary type), C++ #00599c and Rust #ce422b (implementation marks). On dark plots, readable text uses lighter companion colors while bars retain exact implementation colors. Bahnschrift / DIN / Franklin Gothic / Arial industrial sans, tabular numerals; no network fonts. Left alignment, ample line-height, narrow prose.

Desktop: persistent subsystem rail | overview instrument above a single wide newest-first ledger. A single column gives five-case charts room for names, negative bars, whiskers and exact values. Mobile: the rail becomes a labeled subsystem select; export actions wrap; the nonmodal configuration region moves into normal document flow. All core options remain accessible. 44px controls, native selects, contained horizontal table scrolling.

Critique before building: a default hero with a giant average would falsely suggest whole-browser improvement. Instead the heading establishes isolated operations and the aggregate lives in its own explicit instrument, next to interpretation. No decorative glow, gradients, faux status indicators or invented progress counts. Square controls serve the existing export identity; borders separate navigation and control groups, never form a divider below a chart.

Final critique: retain the chart's well-tested shapes and export composition while recoloring only screen output. Prefer long evidence titles wrapping over truncation. History is visible in native run controls and a recorded-date timeline; unknown dates remain unknown.
